# flood_pso_viewer 開発記録

> 起点: 2026-04-30
> 最終更新: 2026-05-07
> 目的: `flood_pso/` の NBT 出力を **ネイティブ GPU で** 閲覧するビューアの実装。
> Web 版（`schematic-renderer` 等）が大規模 NBT でクラッシュしたため、
> 16-32GB メモリ機でも回せる Rust ネイティブ版が必要。

---

## 設計方針

| 軸 | 選択 | 理由 |
|---|---|---|
| 言語 | **Rust** | 高負荷耐性、ゼロコスト抽象、wgpu アクセス |
| ゲームエンジン | **Bevy 0.15** | wgpu/winit のお膳立て、ECS、PBR が標準 |
| 入力 NBT 形式 | Minecraft Structure NBT (gzip) | `flood_pso/nbt_export.py` の出力に一致 |
| パース | **fastnbt** | 高速・人気・serde 統合 |
| メッシュ生成 | **自作 greedy mesher**（rayon 並列） | `mesh_builder_wasm` を参考に書き直し |
| カメラ | **自作 FlyCam**（Minecraft Creative 風）+ bevy_panorbit_camera（軌道） | F キーで切替 |
| UI | bevy_egui | side panel で flood_pso_meta、FPS、capture 状態を表示 |
| マテリアル | **自作 VoxelMaterial**（埋め込み WGSL） | Bevy 標準 PBR が WSL の Mesa GL でシェーダ拡張未対応で落ちるためバイパス |

`schematic-renderer/mesh_builder_wasm` のフルポートは検討したが、
WASM bindings + js-sys + テクスチャ/UV 周りで 1,288 行が絡み合っており、
**flood_pso 用途（マテリアル数 8 / 単色描画）には過剰**。
アルゴリズム設計だけ参考にして、専用シンプル版を新規実装。

## 主な技術メモ

### WSL2 環境固有の問題と回避

| 問題 | 症状 | 解決 |
|---|---|---|
| `GL_EXT_texture_shadow_lod` 未対応 | `pbr_opaque_mesh_pipeline` がシェーダコンパイル失敗で panic | 自作 VoxelMaterial で PBR バイパス |
| Vulkan が lavapipe (CPU) のみ | 描画は成功するが極端に遅い | WSL 検出 (`/proc/version`) して GL を優先順位先頭に |
| DX12 backend は Linux 版 wgpu に無い | DX12 を選んでも fallback | GL 経由 Mesa Zink (GL→Vulkan→D3D12→AMD GPU) で結果的にホスト GPU が掴める |
| `wgpu_hal::gles` の D2/D2Array heuristic warning | ターミナルが ERROR ログ連発で読めない | `LogPlugin::filter` で `wgpu_hal::gles=off` |
| Bevy default far=1000 で大きい world が消える | 黒画面になる | `Projection::Perspective.far = max(10000, world_diag*4)` |
| Default MSAA Sample4 で Zink 上重い | 4倍 fragment work | `Msaa::Off` を camera に挿入 |

### greedy meshing

- `mesh_builder_wasm` を **アルゴリズムだけ参考**にした再実装。WASM bindings/UV/テクスチャ非対応の専用版。
- 6 面方向 × slice 並列で構築（rayon `into_par_iter`）。slice ごとに per-material `MeshBuffer` を作って後で merge。
- `VoxelGrid::set` 中に bbox を更新 → `filled_bbox()` が O(1)。これで md_5m の 380M セルでもフルスキャンせず meshing できる。
- **チャンク分割**：`build_meshes_chunked(grid, CHUNK_XZ=128)` で XZ 方向に 128 ボクセル単位で分割。各チャンク × 各 material が独立 entity になり、Bevy の per-entity frustum culling が画面外を自動カット。

### マテリアル → 色

| Material | 由来 (NBT) | 色 | アルファ | NBT 内のマーカー |
|---|---|---|---|---|
| Stone | `minecraft:stone` | 灰 | 不透明 | |
| Grass | `minecraft:grass_block` | 緑 | 不透明 | |
| Sand | `minecraft:sand` | 砂色 | 不透明 | |
| Gravel | `minecraft:gravel` | 茶灰 | 不透明 | |
| Water | `minecraft:blue_stained_glass` | 青 | α=0.62 | `WaterLayer` |
| Ice | `minecraft:cyan_stained_glass` | 水色 | α=0.55 | `WaterLayer` |
| Bedrock | `minecraft:bedrock` | 黒 | 不透明 | |
| Other | （上記以外） | マゼンタ | 不透明（警告色） | |

`WaterLayer` Component は **V キーで Visibility をトグル** するためのマーカー。

### FlyCam 仕様

- 状態: `yaw`, `pitch`, `speed`, `mouse_sensitivity`, `captured`
- マウス look：`tf.rotation = Quat::from_axis_angle(Y, yaw) * Quat::from_axis_angle(X, pitch)`
  - つまり `forward = (-sin(yaw)*cos(pitch), sin(pitch), -cos(yaw)*cos(pitch))`
  - **yaw 抽出は `atan2(-fx, -fz)`** が正しい（atan2(fx, -fz) は符号バグ）
- 移動：`Quat::from_axis_angle(Y, yaw) * Quat::from_axis_angle(X, pitch)` で得た rotation の `forward`/`right` を使う（pitch 込み）。Space/Shift は world Y で固定。
- Capture：Tab トグル。Locked + visible=false。WSL/WSLg では cursor lock が効かないことがあるが、その場合は cursor が解放されたまま視点だけ動かない状態になりうる（要 invert/Confined fallback 検討、未実装）。

| カテゴリ | キー | 動作 |
|---|---|---|
| Fly モード | W / S / A / D | 視線方向の前後左右（pitch 込み） |
| Fly モード | Space / Shift | ワールド上昇 / 下降 |
| Fly モード | Ctrl 押し | ダッシュ ×4 |
| Fly モード | Mouse | 視点回転（capture 中のみ） |
| Fly モード | Wheel | 移動速度倍率 |
| Fly モード | Tab | マウス capture / release |
| Orbit モード | 左ドラッグ | 軌道回転 |

| Orbit モード | Wheel | ズーム |

## 既知の課題（次セッションへの引き継ぎ）

### A. 性能まわり

1. **WSL2 + Mesa Zink で 10 FPS 程度**：チャンク化で角を見たときの改善は見込めるが、未測定。md_5m を視界全部入れるとやはり重いはず。
   - 対策候補：LOD（遠距離は粗い voxel 表現）、distance fog で far を縮める、チャンク粒度を 64 に細分化
2. **dense grid のメモリ**：huge_5m (15km × 15km @ 5m) で 3000 × ny × 3000 ≈ 数GB。chunk-based sparse 表現が必要。
3. **起動時の重複メッシュ計算**：`main.rs` で stats 取得用に `build_meshes` 1 回 → `spawn_voxel_world` 内で `build_meshes_chunked` 1 回、合計 ~5s。共通化可能。

### B. UX まわり

1. **WSLg で cursor lock が完全には効かないケース**：Tab で capture しても cursor が窓外へ抜ける症状の可能性あり。`CursorGrabMode::Confined` への fallback、または右クリック with mouse-look の併用を検討。
2. **マウス Y 反転オプションが無い**：Bevy 0.15 / winit / WSLg の組み合わせで `MouseMotion.delta.y` の符号が環境依存になり得る。`--invert-y` フラグ追加の余地。
3. **テクスチャ未対応**：マテリアル別単色のみ。Minecraft resource pack を読みたい場合は `schematic-renderer` の `ResourcePackManager` 系を参考に実装。
4. **シャドウ未対応**：大規模 quad 数で重いため OFF。後で cascaded shadow を追加可能。

### C. 機能拡張候補

1. **複数 NBT を同時ロード**：PSO vs CCPSO2 vs GT を並べて比較したい
2. **dh_map ヒートマップを地表に投影**：egui のミニヒートマップに加え、3D 地形上に色分けで重ねる
3. **flood_pso_meta クエリ**：CLI から `--query method=ccpso2 --query K=16` でフィルタ
4. **schematic / litematic 対応**：fastnbt パーサを差し替えれば対応可能

## クイックスタート（次セッション用）

### ビルド

```bash
cd /home/moriken/web-app/flood_pso_viewer

# 初回のみ：システム依存
sudo apt install -y libxkbcommon-x11-0 libx11-6 libxi6 libxcursor1 libxrandr2 libxinerama1 libgl1

cargo build --release
```

### 実行

```bash
# 推奨：軽い NBT で動作確認
./target/release/flood_pso_viewer ../flood_pso/results/nbt/gobo_xs_overview.nbt

# 本番：CCPSO2 の高次元洪水校正結果
./target/release/flood_pso_viewer ../flood_pso/results/nbt/hd/gobo_hd_K16_seed0_md_5m_ccpso2.nbt

# 浸水前モード
./target/release/flood_pso_viewer <NBT> --no-water

# 軌道カメラで起動
./target/release/flood_pso_viewer <NBT> --camera orbit

# バックエンド強制
FLOOD_PSO_VIEWER_BACKEND=vulkan ./target/release/flood_pso_viewer <NBT>
```

### 確認のフロー

1. 起動直後：右パネル上部に FPS と `○ mouse: free (Tab to capture)` が表示
2. **Tab** でマウス lock → ステータスが `● mouse: CAPTURED` に
3. **WASD/Space/Shift** で飛行、**マウス** で視点
4. **F** で Orbit ↔ Fly 切替（orbit 中心は世界中心に snap）
5. **V** で水・氷の ON/OFF
6. **Esc** で終了
